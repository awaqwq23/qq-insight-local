# 会话 AI 聊天、三类记忆和多模态附件（0.15.0-rel）

0.16起，本文关于画像强制原文及失败后覆盖的规则由[ai-v13.md](ai-v13.md)取代：先复用核验上下文、增量压缩独立保存，再执行任务，必要时回源。下文保留0.15接口的历史说明。

继承 ai-v10/v11 的受控工具、预算、证据和分支规则。日常群/私聊入口改为聊天页，旧功能表单不再作为主入口；旧结果由“记忆与设置 → Agent设置 → 旧版分析存档”查看。

## 对话范围

`workspace_sessions` 增加 `conversation_id TEXT NOT NULL DEFAULT ''`。空值为全局对话，非空值永久绑定当前账号的一个 QQ 群或私聊。`chat.create/list` 可传该参数；list 默认只列全局对话。get/rename/select 仍按对话ID及账号校验，不改变其绑定。每个会话可保存多个主题，打开会话进入已保存的最近对话，可继续追问或编辑旧问题。主题之间的问答仍隔离，来源会话记忆共享。

`workspace.begin` 增加 `conversation_id`、`attachment_ids`。已有session的绑定为准，不允许调用者换成别的会话。固定群或私聊的 conversations、people、read_context、statistics、export_order、images、memory 及写入工具只能访问此会话。固定私聊无需每轮再出现“私聊”字样；全局对话继续默认群聊，明确要求私聊才开放，新的群聊问题过滤旧私聊问答和本人观察。

预设是可修改的用户输入：今日重点、任务清单、群/双方画像、人物风格、表情收藏。点击只填入输入框，不启动分析或产生调用。用户也可直接聊天、让Agent检索记录、修改软件工作区或生成文件。支持常用Markdown段落、标题、列表、粗体和代码显示；HTML始终转义。

## 本地记忆与Agent

在同一应用SQLite中按账号/会话逻辑隔离三个记忆库，统一备份：

1. 会话概括：既有 `ai_memories(kind=group)`，群保存用途、事实、变化与暂定评价；私聊保存关系背景和讨论事项。多会话综合推断不会拆成单会话事实。
2. 成员与本人：`ai_memories(kind=person)`，按QQ/UID保存有本人发言来源的观察；从独立成员缓存、已导入发言者和本人构建名册，未发言/证据不足的人保持未知。私聊另有人工填写的本人和对方身份；人工身份标为用户设定。
3. 消息记忆：`ai_message_memory`逐消息保存哈希与本地摘录，`ai_contexts`保存分析摘要及来源哈希。前者规范分钟时间、保留来源ID并有界截短正文/引用；后者复用前校验全部来源。均不能代替精确原文。

`conversation_agents(settings_json,learned_json)`分别保存人工Prompt/本会话身份和根据有来源观察生成的Agent背景。每次成功读取分析后保存消息摘录及相应观察，更新自动背景；画像/身份分析在没有读取原记录时拒绝finish，要求先读取。人工Prompt和身份不会被自动背景覆盖，用户更正锁定优先。原消息相关内容变化触发摘录失效并清除旧自动背景；手动更正/忘记使对应语义摘要和旧背景失效。

初始请求只预载部分相关概括、锁定纠正和本人观察，其余通过memory工具选择读取。暂停会话不读取/更新其AI记忆、自动背景或摘要缓存，普通原记录浏览仍可用。模型画像只是带来源的观察，不保证真实性格或语义正确率。

`account_self_profiles`按账号保存全局称呼、QQ/UID、身份与偏好；用户可以在全局聊天“我的设置”，或会话设置的“全局我的设置”中编辑。本人AI观察保留来源会话，通过self.memory查看，给全局模型时仍按群/私聊范围过滤。全局身份不自动变成每个群的角色。本人的消息通过账号、明确配置的QQ/UID及本地身份配对识别，显示在右侧；方向筛选沿用同一识别规则。

## 进度与复用

`chat.memory.coverage`返回total/read/unread/compressed及不连续的序号区间（按原记录时间正序、同秒按本地ID）。只将成功分析覆盖的原记录或哈希校验通过的旧摘要计入；不把导入、纯聊天、用户补充记忆或失败调用当成已读。序号随新导入变化，消息正文/元数据变化后重新计为未读。

read_context新增unread_only，可准确读取尚未覆盖或已变化记录。暂停记忆时不使用此筛选。默认智能选择有效摘要/摘录和新原文；摘要未节省材料就读原文。原话、画像、身份、风格、数字和顺序任务由核心禁止复用有损摘要/摘录；计数和顺序工具基于原库SQL。模型仍需选择正确查询，未覆盖范围不得声称全量。当前轮读到的来源哈希在finish时再次核对。字节节省不是计费Token。

## 受控数据库修改

- memory：按会话选择读取概括、人物或消息记忆。
- update_memory：仅在当前用户明确要求时correct/forget/unlock；remember保存用户主动补充的记忆，锁定并注明“用户补充，尚非聊天核验事实”，不推进聊天读取量。
- update_agent：当前用户明确要求时保存本会话Prompt、本人/对方身份或记忆开关。
- update_self：用户明确要求修改全局自己的资料时保存，不能用第三方聊天或附件授权。

这些操作只改应用拥有的表。模型没有任意SQL、任意路径、任意命令、QQ源库写入或发消息权限。生成MD/XLSX/图片继续使用受控文件ID和原生打开/另存为。

## 多模态附件

群聊、私聊和全局共用“图片/语音/文本”入口。专用workspace:attachments.pick打开原生选择器，不接收渲染器提供的文件路径；按当前账号及session保存。每轮最多4份、每份8MB，UTF-8文本最多10万字。支持PNG/JPEG/GIF/WebP；WAV/MP3/M4A/OGG；TXT/MD/CSV/JSON/LOG。其他格式需先转换，不承诺PDF、视频或任意Office文件解析。

`workspace_attachments`保存自有附件，`workspace_run_attachments`绑定已提交轮次。begin拒绝跨账号/对话附件；attachments和inspect_attachment只读取本轮及当前分支此前提交的附件，不能读取其他对话/旧分支。

图片先实际识图，语音先实际转写，均使用独立媒体配置并记入预算/用量；文本有界分页读取，offset/next_offset使用Unicode字符偏移，has_more明确未读完。附件是用户提供的不可信材料，不是QQ消息证据，不能借它写成他人的本人发言画像。缺少媒体配置、预算或模型失败保留问题、附件和失败步骤，不自动重复发送。

attachment.add/data/observed、begin/tool/finish仍为主进程专用，通用界面RPC不可直接调用。self.get/save/memory、chat.settings.get/save、chat.memory.list/coverage为显式设置及查看接口。对话、附件、设定与三类记忆随备份恢复，校验归属、来源、分支无环及附件内容；旧版缺少新增字段/表可导入，不执行来源库DDL。

## 验证与边界

test_chat_memory.py、renderer-conversation.test.js、workspace-agent.test.js、main-smoke.test.js与packaged-people-smoke.py使用合成资料验证作用域、持久化、三类记忆、更新限制、附件识图/转写调用、文本分页和实际stdio。模型返回由合成替身提供，不是在线模型或真人画像验收。任务仍受16次逻辑模型调用及预算/容量限制；过大任务须分段，未覆盖项必须说明。三角色多轮核查/裁决仍属R04待实现内容。

升级前可在“设置 → 数据与账号”导出数据库备份。新版可导入旧版备份；历史程序不保证能写入新版对话结构，回退时请使用升级前的备份。
