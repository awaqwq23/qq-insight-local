# 官网全体成员导出 v2（0.10.0-rel）

用户于 2026-10-23 明确选择“新增官网扫码登录导出”；该入口是本地分析功能之外的独立、显式联网只读功能。不发消息、不修改群或成员、不向模型发送名单。

## 入口与边界

- 当前群顶部“导出全体成员（官网）” → preload `exportFullRoster` → 专用 `roster:export-full` IPC。
- 主进程通过私有 `roster.scope({account_id,conversation_id,platform:'qq'})` 校验本地会话归属，取得真实群号；账号标识必须是真实 QQ 号，缺失群号或任意账号标签均拒绝。
- 创建无持久化分区、无 preload、禁用 Node、启用 sandbox/contextIsolation/webSecurity 的官网窗口。用户自行登录对应 QQ，关闭窗口取消。拒绝弹窗、下载与设备权限；管理接口仅允许读取群列表与查询成员，修改群名片／管理权限／移除成员等请求均拦截。
- 官网入口：[QQ群成员管理](https://qun.qq.com/member.html)。当前公开页面脚本使用 `QunHandler.request`，只读查询路径 `/cgi-bin/qun_mgr/search_group_members`，POST 字段 `gc,st,end,sort`；`st/end` 含首尾，每页21条。不枚举猜测其他接口，官网变更或无权限时失败并提示。
- 登录身份在每页请求前后核对：官网 `uin/p_uin` 必须与当前 QQ 账号一致，且已获得官网登录会话。Cookie 不返回应用界面、不落入设置或日志；独立会话结束后清理 Cookie／存储与缓存。最多10分钟，单页请求20秒、外层25秒超时。
- 不接受渲染器传入群号、名单、Cookie 或文件路径。群号来自受限核心，名单来自官网固定查询，保存位置仅由主进程原生对话框选定。

## 完整性与输出

- 每页要求 `ec=0`、有效总人数与成员数组；保留 QQ 原昵称 `nick`、群名片 `card`，成员标识使用 `uin`。
- 空页、短页未达总数、身份重复、人数变更、登录变化、超限、官网拒绝或无效字段均中止，不输出部分名单。总数上限100000。
- 全部分页去重后人数与各页报告的总人数一致，才显示 CSV 保存对话框。名单是一次分页读取结果，期间有成员变化可能需要重试，并非服务端原子快照。
- 私有 `roster.export` 新增 `kind:'full_members', online:{account_id,group_qq,count,members:[{qq,nickname,card}]}`；核心再次校验归属、数量、身份唯一性和字段，拒绝不完整数据。
- CSV 与 v1 复用相同 UTF-8 BOM、转义、公式防护与不覆盖写入逻辑，增加导出时间列。包含未发言成员；不把本地历史发言者混入官网名单，以免混入已退群者。名单不写回本地联系人或聊天数据库。
- `roster.scope` 与 `roster.export` 均不在通用 renderer RPC 白名单。专用入口同时只允许一项在线导出。

## 验证范围

合成测试覆盖三页分页、未发言成员、总数变化、重复／缺失页、账号变化、权限拒绝、CSV 双名称与取消、凭据会话清理、管理写请求拦截及界面入口。合成数据不能证明某个真实账号拥有官网群成员读取权限；首次使用仍须用户登录实测。

保留 v1 的“导出发言成员”和“导出群列表”，它们仍只读本地数据。
