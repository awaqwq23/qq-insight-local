# MVP 导入更新契约 v1（向后兼容扩展）

`source.prepare` / `source.import` 新增 `import_mode`：`incremental`（默认）或 `full`。桌面 `prepareSource` 对应 `importMode`。非法值返回 INVALID_PARAMS。

- 增量：按账号比较消息身份及源字段摘要，只解析/写入新增或变化的消息；不以发送时间或最大消息ID裁剪，保留迟到旧消息、同时间消息与旧消息修订。仍需扫描有变化的消息快照，当前不宣称只解密增量页。
- 全量：忽略已导入快捷返回，重新解析当前源库全部消息及资料，用于完整校验/修复投影；不删除已导入而当前源库缺失的历史。
- 首次导入/投影版本变化自动全量。消息、FTS、变更序号、资料、导入完成标记在同一事务提交；失败不前移检查点。
- 联系人/群资料逐条比较；只回填变化记录关联的会话/消息。新增消息从已保存资料补全。数据库内容摘要不变时跳过对应资料库解密；失败的可选资料库不保存完成标记，下次重试。
- 新增返回 `import_mode`（实际执行模式）、`changes:{scanned,added,updated,unchanged}`、`metadata:{profiles,groups,local_avatars}`（实际处理变化数，全量为处理条数）、`last_change_seq`（本应用入库顺序，与QQ发送时间不同）、`warnings`（可选资料未完成）。`total/c2c_count/group_count` 保持源快照消息总量语义。
- `already_imported` 仅表示当前源消息和所有可读资料均已处理；资料单独变化也会更新，不被消息文件无变化短路。未实现云模型增量分析；本次增量范围为本地导入/解析与资料更新。

验收：新增、同时间/旧日期晚到、修改已有消息、资料单独改名、未变资料不写回、新消息使用缓存资料、全量修复、账号隔离、失败回滚、可选库失败重试、旧索引迁移；合成5万消息/1000联系人前后对比。
