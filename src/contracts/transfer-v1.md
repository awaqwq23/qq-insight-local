# 本地数据库传输契约 v1

本次跨 M01/M02/M03/M04/M10/M11：数据库批量写入、手动 QQ 导入、应用库合并和一致性导出需要共用事务、账号范围与桌面文件选择边界。

- `source.manual_import(path, format, account_id="", database_key="", import_mode="incremental")`：format 为 `qq_encrypted`、`qq_plain` 或 `app_db`。QQ 导入必须明确账号；加密导入必须提供对应的 16 字符 ASCII 密钥，不启动 QQ 或自动取钥。支持重命名的 NTQQ 加密文件（1024 字节头）。明文导入自动读取同目录明文资料库。成功返回既有导入统计；失败不提交检查点。
- `archive.export(path)`：SQLite backup 一致性快照，导出所有账号的消息、资料、角色及应用数据；不包含设置文件中的 QQ 密钥/API Key，不打包媒体文件。输出普通 SQLite `.db`，包含 `archive_manifest` 格式版本 1。原子写入；禁止覆盖正在使用的应用库、QQ 库或其他已有文件。
- `app_db` 导入：接受格式 v1 或兼容的旧版 `assistant.db`，先在私有目录固定 DB/WAL，再校验结构、完整性与账号范围。在一个事务中合并消息、会话及资料；重复消息保留当前版本，新增消息建立全文索引与本地变更序号；保留当前角色（为空时恢复备份角色）。不导入源库检查点或密钥。返回 `status=merged, added, skipped, account_ids`。
- `source.discover` 增加 `accounts`：已导入但本机无 QQ 数据源的账号也可浏览。`items` 仍只表示可自动更新的数据源。
- 文件路径由主进程系统选择器绑定令牌；renderer 只持有令牌和文件名。导出由系统保存对话框指定新文件。手动输入密钥仅用于本次操作，提交后清空，不写日志或存储。
- 无效文件、版本不兼容、账号不匹配、源文件正在变化或写入失败均返回明确错误；导入事务整体回滚。所有查询、进度和原有导入接口保持兼容。

验收覆盖：明文/加密（合成 SQLCipher 库）、应用库含 WAL、合并去重、冲突保留、账号隔离、原子回滚、旧库兼容、导出重新导入、拒绝覆盖和错误格式。真实 QQ 版本兼容需独立实测。
